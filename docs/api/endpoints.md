# Endpoints

> Responsibility: catalog of `signa-api` endpoints the web calls, via `src/lib/api/`.
> Update when: an endpoint call is added, changed, or removed, or a stub becomes real.
> Sources: src/lib/api/auth.ts, src/lib/api/organizations.ts, src/lib/api/invitations.ts, src/lib/api/admin.ts

Types → [types.md](./types.md). Client behavior → [http-client.md](./http-client.md). The API's own contract is authoritative (`signa-api` controllers / Swagger).

## `authApi` (`src/lib/api/auth.ts`) — mirrors `AuthController`

| Method                              | Path                               | Returns        | Notes                                                           |
| ----------------------------------- | ---------------------------------- | -------------- | --------------------------------------------------------------- |
| `login(identifier, password)`       | `POST /auth/login`                 | `AuthResponse` | `identifier` = email or username. Anonymous                     |
| `forgotPassword(email)`             | `POST /auth/forgot-password`       | `void`         | Anonymous; API answers the same whether or not the email exists |
| `resetPassword(token, newPassword)` | `POST /auth/reset-password?token=` | `void`         | `token` is a **query param**. Anonymous                         |

Refresh (`POST /auth/refresh`) is called internally by the client, not exposed as a module method.

## `organizationsApi` (`src/lib/api/organizations.ts`) — mirrors `Organization*Controller`

| Method                           | Path                                          | Returns                           | Notes                                                                                                                                                                                                                                                                                                 |
| -------------------------------- | --------------------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `me()`                           | `GET /organizations/me`                       | `MyOrganization`                  | Used at login to find the org and confirm `role === "ADMIN"`                                                                                                                                                                                                                                          |
| `redeemInviteCode(code)`         | `POST /organizations/invite-codes/redeem`     | `RedeemInviteCodeResponse`        | Admin invitations only (the API rejects participant codes); for the reserved accept-invite flow                                                                                                                                                                                                       |
| `overview(orgId, params)`        | `GET /organizations/{id}/overview`            | `OrganizationOverview`            | Participation / progress / performance; `courseId` narrows to one contracted course, `period` → `from`/`to` (see below)                                                                                                                                                                               |
| `activity(orgId, params)`        | `GET /organizations/{id}/activity`            | `OrganizationActivity`            | Params `period` → `from`/`to`, `courseId`. Day-by-day figures in Argentina's calendar plus period totals; the whole history starts on the day the organization was created. Feeds the overview's period card                                                                                          |
| `members(orgId, params)`         | `GET /organizations/{id}/members`             | `Page<OrganizationMemberSummary>` | Spring `Page`; params `query`, `status` (`ACTIVE` default / `REMOVED`), `activity` (`ACTIVE`/`INACTIVE`/`NOT_STARTED`/`COMPLETED`), `courseId`, `period` → `from`/`to`, `sort` (`name`/`progress`/`lastActivity`/`joinedAt` + `,asc`/`,desc`), `page`, `size`. Sorted, filtered and paged server-side |
| `member(orgId, userId, period?)` | `GET /organizations/{id}/members/{userId}`    | `MemberProgress`                  | Per-participant progress and per-course breakdown; `period` → `from`/`to`                                                                                                                                                                                                                             |
| `removeMember(orgId, userId)`    | `DELETE /organizations/{id}/members/{userId}` | `void`                            | 204                                                                                                                                                                                                                                                                                                   |
| `modules(orgId, params)`         | `GET /organizations/{id}/modules`             | `ModuleStats[]`                   | Per-module completion and accuracy; `courseId` narrows to one course, `period` → `from`/`to`                                                                                                                                                                                                          |

| `catalog()` | `GET /organizations/catalog` | `PurchaseCatalog` | Anonymous. Paid courses with a published version, their sign count and `modules[{title, signs}]` (the words, shown before buying), plus `volumeDiscounts` and the range settings |
| `quote(params)` | `GET /organizations/catalog/quote` | `PurchaseQuote` | Anonymous. `courseId`, `seats`, `durationDays` → list price per seat, volume discount, price per seat, subtotal and total (signa-api `PurchasePricing`: `(6000 + 400 × signs) × (days/30)^0.85`, rounded to $10, minus 10/15/20/25 % from 10/25/50/100 seats) |
| `purchases(orgId)` | `GET /organizations/{id}/purchases` | `Purchase[]` | Newest first, with `seatCounts` per state |
| `purchase(orgId, id)` | `GET /organizations/{id}/purchases/{id}` | `PurchaseDetail` | Purchase + seats |
| `createPurchase(orgId, data)` | `POST /organizations/{id}/purchases` | `PurchaseDetail` | `{courseId, durationDays, emails}`; 400 if the org is not validated, 409 if an email already holds a live seat of that course. Starts `PENDING_PAYMENT` |
| `cancelPurchase(orgId, id)` | `POST /organizations/{id}/purchases/{id}/cancel` | `PurchaseDetail` | Only before payment; also expires the Mercado Pago checkout (best effort) |
| `checkout(orgId, id)` | `POST /organizations/{id}/purchases/{id}/checkout` | `PurchaseCheckout` | Creates a Mercado Pago Checkout Pro order (Orders API); the panel navigates to `checkoutUrl`. 400 if already paid/cancelled, 503 if Mercado Pago is not configured or fails |
| `syncPayment(orgId, id)` | `POST /organizations/{id}/purchases/{id}/payments/sync` | `PaymentSync` | No body: the API re-reads the Mercado Pago order it stored for the purchase (never an id from the browser) and confirms the purchase if it is processed and matches the total (same rule as the webhook); an approved payment that cannot pay it (cancelled, already paid, other amount) is refunded in full and listed in `refunds`. 400 if no checkout was started. Returns the order's `paymentStatus` (Orders vocabulary: `processed`→`approved`, `failed`, `canceled`, `expired`, `action_required`…) |
| `withdrawPurchase(orgId, id, reason?)` | `POST /organizations/{id}/purchases/{id}/refund` | `PurchaseDetail` | Withdrawal: `{reason}` optional (≤ 500). Only a `PAID` purchase paid with Mercado Pago while `refundableUntil` has not passed (10 days from payment); 400 otherwise. The API records the refund, refunds the whole payment in Mercado Pago and only then revokes the purchase (`REFUNDED`: pending invitations cancelled, active accesses end, progress kept). 503 if Mercado Pago fails: the refund stays pending and retrying completes it (never twice) |
| `updateSeatEmail(orgId, p, s, e)` | `PATCH …/purchases/{id}/seats/{seatId}` | `PurchaseDetail` | Only while pending; re-sends with a new link, the deadline does not move |
| `remindSeat(orgId, p, s)` | `POST …/purchases/{id}/seats/{seatId}/reminders` | `PurchaseDetail` | Pending invitations only, one per 24 h (400 otherwise) |

## `adminApi` purchases (`src/lib/api/admin.ts`)

`purchases(status?)` → `GET /admin/purchases`; `confirmPayment(id, reference?)` → `POST /admin/purchases/{id}/confirm-payment`. The same confirmation Mercado Pago triggers (webhook `POST /payments/mercado-pago/webhook` in signa-api, or the panel's `syncPayment`); the back-office stays as a manual fallback.

**Period (`from`/`to`).** `overview`, `activity`, `modules`, `members` and `member` take an optional `period` (`src/lib/date-range.ts`), sent as `from`/`to` ISO dates (inclusive, Argentina's calendar, both or neither, at most 366 days; `null` sends neither = the whole history). `signa-api` (`MetricsPeriod`) counts what _happened_ inside the period (attempts, correct %, lessons and modules completed, minutes, active days, who was active) and measures _states_ as of its end (progress %, who finished, current module, in-progress/completed per module, who had joined). Streaks are always current. With no period, "active" keeps the rolling windows (7 days for people, 30 for active days) and `participation.activeWindowDays` says which; with one, it is the period's length.

## `adminApi` sign reports (`src/lib/api/admin.ts`)

`signReports(filters?)` → `GET /admin/sign-reports` returns **individual** reports (`AdminSignReport[]`, newest first), each managed on its own. Optional filters sent as query params: `status`, `reason` (tipo), `signQuery` (substring match on the sign meaning), and `from`/`to` (ISO dates, inclusive). `updateSignReport(reportId, status, adminNote?)` → `PATCH /admin/sign-reports/{reportId}` sets the status and optional internal note; moving to `RESOLVED`/`REJECTED` records the acting admin on the backend (surfaced as `resolvedBy` + `resolvedAt`).

## `metricsApi` (`src/lib/api/metrics.ts`) — usage dashboard

| Method                 | Path                               | Returns               | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------- | ---------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `business(params)`     | `GET /admin/metrics/business`      | `BusinessMetrics`     | Global business snapshot (all users, with/without org). `params` = `{ from, to }` ISO-8601 **instants**. Courses/versions/enrollments/progress/accuracy/errors + a daily activity series                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `growth(params)`       | `GET /admin/metrics/growth`        | `GrowthMetrics`       | Global growth & business snapshot for the "Negocio" apartado. `params` = `{ from, to }` ISO-8601 **instants**. Audience (signups + total, new users with the previous-window count + activation), engagement (DAU/WAU/MAU + stickiness + active-in-range with the previous window), sessions (per user + avg duration, from app telemetry), weekly retention cohorts (D1/D7/D30), waitlist, B2B revenue/refunds, **end-user (sin organización) gem & paid-course revenue/refunds** (money + units: `gems.{paidAmount,gemsGranted,refundedAmount,refundedCount}` + amount series, `courseSales.{paidAmount,purchases,refundedAmount,refundedCount}` + amount series), seat utilization, orgs by status + B2B deep-dive (pending/new orgs, avg users & revenue per org, purchases, per-org license utilization table, free→premium conversion); adaptive-resolution series |
| `learning(params)`     | `GET /admin/metrics/learning`      | `LearningMetrics`     | Global learning & content snapshot for the "Aprendizaje" apartado. `params` = `{ from, to }` ISO-8601 **instants**. Per-course completion, enrollment funnel, hardest lessons by accuracy, vocabulary growth (daily), sign-report resolution + most-reported signs, import health; plus learning depth: lessons started/completed + completion rate, exercises attempted/success/avg attempts, onboarding funnel, lesson abandonment ranking, exercise error/retry rankings, daily accuracy                                                                                                                                                                                                                                                                                                                                                                              |
| `gamification(params)` | `GET /admin/metrics/gamification`  | `GamificationMetrics` | Global gamification & engagement snapshot for the "Gamificación" apartado. `params` = `{ from, to }` ISO-8601 **instants**. Daily XP + XP per active user, streak distribution + max streak, achievements unlocked + unlock rate + most/least unlocked, challenge claim rates by type, gifts, XP distribution tiers, shop economy (gems spent, gem redemption rate, top items)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `perf(widget, params)` | `GET /admin/metrics/perf/{widget}` | `PerfMetrics`         | Performance/infra time series proxied from Grafana Cloud. `widget` is a fixed catalog key (`latency_p95`, `cpu_host`, `error_rate`, `animation_latency`, …). `params` = `{ from, to, step? }`. `available=false` ⇒ Grafana read token not configured                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

Telemetry ingestion (`POST /telemetry/events`) is **not** called from `metricsApi` — it is the write
side used by the client telemetry util (`src/lib/telemetry.ts`) and by `signa-mobile`.
