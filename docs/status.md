## Real

- Scaffold: Next.js 16, TypeScript strict, Tailwind v4 tokens, ESLint/Prettier/Vitest, CI (`ci.yml`, `branch-policy.yml`, `release.yml`).
- API client (Bearer, casing, single-flight refresh), in-memory token store, `AuthProvider`, and the session Route Handlers (`/api/session/*`, `HttpOnly` refresh cookie) — [api/session.md](./api/session.md).
- **Org login/register** at `/organizations/login` (CUIT validated; the organization is created `PENDING` until SIGNA validates it) and the guarded **org panel**: overview, members list + detail (remove), contents, all filtered by course and by a global period (Desde / Hasta); the participants screen has two tabs, **Participantes** and **Invitados** (seats not yet accepted, with remind and change-email actions) and shows "Cuenta eliminada" for erased accounts; the org admin's own photo at `/dashboard/profile` — see [features/dashboard.md](./features/dashboard.md).
- **Seat purchases** (org panel): course preview before buying (sampled signs played as 3D or video, resolved by `POST /signs/media`), buy with a summary before paying, pay with Mercado Pago Checkout Pro, track, change pending emails, remind, cancel, withdraw within 10 days, and **request a refund** after the window ("Pedir reembolso", `POST …/refund-request`).
- **Org password recovery** at `/organizations/forgot-password`: 6-digit emailed code + new password, then automatic sign-in (same flow as `signa-mobile`).
- `/invitacion` — employees accept a seat invitation: log in (email/password or **Google**) or create the account with the invited email.
- Back-office (SIGNA), all under `(admin)` with its own `AdminAuthProvider`:
  - `/admin` Resumen, `/admin/organizations` (approve / reject / suspend with reason / reactivate / delete), `/admin/sign-reports`, `/admin/users` (Usuarios with a role-aware detail modal · Administradores · Lista de espera), `/admin/profile`.
  - Administradores: list, create (with photo) and edit admins (name, email, password, photo). The photo is a 256 px JPEG data URL stored in `users.avatar` (no object storage yet); any account can set its own through `PUT /users/me/avatar`; the API serves it from `GET /users/{username}/avatar` and responses carry a versioned `avatarUrl`.
  - `/admin/courses` — course CMS (versions, fork, editor, publish/archive).
  - `/admin/signs` — sign catalog editor: rename (cascades), handedness, YouTube, upload `.glb` / `.mp4` (+ lateral), usage per lesson — [features/admin-signs.md](./features/admin-signs.md).
  - `/admin/purchases` — unified view of SEATS / GEMS / COURSE purchases + **Reembolsos** (refund requests) tab. **Read-only for payments: the manual payment confirmation was removed** (Mercado Pago webhook / the panel's sync confirm them). Detail in [features/dashboard.md](./features/dashboard.md#admin--compras-adminpurchases).
  - `/admin/usage-metrics` — global usage dashboard in tabs (Resumen · Negocio · Usuarios · Aprendizaje · Infraestructura[Backend/Web/ML]): KPI cards with period-over-period deltas, "Requiere atención", services strip, self-documenting widgets through a central metric catalog; business data from signa-api Postgres, performance/infra proxied from Grafana Cloud; one datetime range picker with a live toggle; dragging across a chart re-filters every widget — [features/admin-usage-metrics.md](./features/admin-usage-metrics.md).
  - The old "Cursos y señas" screen (`/admin/content`) and the manual YAML import button are gone (the API still imports on startup).
- Client RUM (`src/lib/telemetry.ts`, initialized in `providers.tsx`): native PerformanceObserver web vitals (LCP/FCP/TTFB/CLS) + error listeners, batched to signa-api `POST /telemetry/events` (best-effort, `sendBeacon`). Dependency-free — no `web-vitals` package. Works on the landing too: `connect-src` has the API origin in both CSP tiers.
- Landing page (`/`) — full one-page site with a playable 3D lesson demo; scroll effects work in every browser (no CSS scroll timelines) — [features/landing.md](./features/landing.md).
- Landing camera demo ("Tu cámara te corrige") — real in-browser recognition: spell your name with the LSA alphabet, signa-ml v8 (v5 plus S, O and C recorded on an iPhone and the Z, which also needs its trace; the native app still ships v5).
- `/organizations` — organizations marketing page; `/proximamente` — coming-soon page with waitlist email form: the browser calls signa-api `POST /waitlist` directly (202 for valid emails; rate limiting is done by Cloudflare in front of the API), validates the email first, has a hidden honeypot field and a minimum fill time, and shows the real result. All "Empezá gratis" CTAs link here.
- Security headers + two-tier CSP (strict nonce for the panel, relaxed static for the landing) — [security.md](./security.md).
